# 多步骤决策分析工作流模型方案

## 第一版固定组合

| 节点 | 模型 | 参数 | 原因 |
|---|---|---|---|
| 意图识别、参数提取 | `qwen-plus-2025-07-28` | 温度 `0`，最大输出 `1200` | 与普通 `qwen-plus` 的免费额度独立；长上下文、结构化输出和工具调用能力适合路由节点 |
| 决策分析与最终回答 | `qwen-max` | 温度 `0.1`，最大输出 `4000` | 用量只集中在最后一个节点；适合把多组工具证据组织成管理层可读结论 |
| 数字与来源复核 | Dify Code 节点 | 不使用模型 | 避免第二次消耗 Token，并阻止模型修改工具数字 |

## 如果免费额度列表中还有更新模型

按以下优先级替换：

1. 最终决策节点：`qwen3.7-plus` > `qwen-max` > `glm-5`。
2. 路由和参数提取：`qwen3.6-flash` > `qwen-plus-2025-07-28`。
3. `glm-5` 先作为人工对照模型。用相同的 10 个问题测试 JSON 合法率、数字一致率和中文建议质量，全部通过后再替换主模型。

不要用于本工作流主链：

- `qwen-mt-flash`：面向翻译，不是经营决策模型。
- `qwen3-vl-30b-a3b-thinking`：本流程没有图片输入，使用视觉模型会浪费额度和延迟。
- `deepseek-r1-distill-qwen-7b`：可以做低成本实验，但 7B 蒸馏模型不承担参数提取、严格 JSON 和最终管理建议。

## Token 控制

- 工具结果先在 Code 节点裁剪，再交给最终模型。
- 每类明细最多保留 10 条，高风险或金额最高的条目优先。
- 不把聊天全历史传入模型，只传本轮问题、已确认实体、工具证据和上一轮已经确认的业务对象。
- 最终节点只运行一次；数字复核不用第二个 LLM。
- 模型免费额度即将耗尽时，在 Dify 中人工切换模型，不配置跨厂商自动失败转移。
