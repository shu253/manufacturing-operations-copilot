# AI 解决方案工程师视角

## 项目中的解决方案工作

1. 将“老板看不到跨系统经营风险”转化为订单、采购、生产、成本和应收五类可落地场景。
2. 明确产品不替代 ERP/MES，而是通过适配层复用客户现有数据和流程。
3. 设计数据层、计算引擎、受控工具、Dify编排和多渠道交互的总体架构。
4. 将复杂问题拆成可验收的工具调用链，并定义缺参追问、异常分支和可信回答边界。
5. 设计老板/厂长到部门负责人的轻量行动闭环，不扩张为完整 OA。
6. 形成从数据盘点、接口映射、规则确认、UAT 到生产部署的实施路径。

## 可用于面试的重点

- 为什么是离散制造、面向订单，而不是流程制造。
- 为什么不能让大模型直连数据库或直接计算金额。
- 如何将 ERP、MES、WMS、采购和财务数据映射为统一业务对象。
- 如何处理数据日期、业务口径、截断、冲突和工具失败。
- Demo如何迁移到客户内网、企业身份和正式数据库。
- 如何定义项目范围、验收用例和生产安全边界。

## 一句话介绍

我围绕离散制造企业订单交付问题，设计了一个叠加在现有 ERP/MES 之上的经营管理智能体，通过确定性计算与受控大模型编排实现跨环节风险分析，并通过飞书人工确认和回执形成轻量执行闭环。
